## Rig finding

The actual GLB hierarchy is **Thigh → Calf → Foot → ToeBase**, a direct deform chain. ThighTwist and CalfTwist are **side branches**, not intermediate parents. Analytical IK can therefore rotate the direct chain and let twist branches inherit normally. The helpers modify leg rotations only; they do not layer pelvis/hips separately from torso. Full upper-body and sickle world matrices were identical in the paired CPU checks. The exploratory candidate additionally holds ToeBase orientation during support and applies swing-foot clearance.

## Evidence and rejection, without proxy substitution

`tools/enemy-locomotion-contact-cpu.mjs` runs paired actual controllers at 1.0, 3.7 and 5.5 m/s, curved motion, a hard turn and a teleport. Every geometry scan includes the full skinned body. Independent ground-contact statistics use **2,159 unique Foot/Toe-weighted surface vertices**, each actor's own geometry at world Y ≤35 mm and vertical speed ≤0.35 m/s. They are independent of the solver's contact/locked telemetry. Actual physical-device/playback proof remains separate.

The first helper produced near-zero drift at its selected ball marker over only 11–13% of each foot's cycle. **Broader ground-surface Run drift was unchanged.** That selected-marker success did not satisfy the task, so contact correction is disabled by default. # Orc Peon: distinct Mixamo Run candidate

Implemented 2026-09-18. This is a locomotion candidate, not a no-sliding or 10/10 acceptance claim.

`src/assets/enemy-library.js` now loads `assets/models/orc-peon-locomotion-v1.glb`. The previous `orc-peon.glb` remains untouched at SHA-256 `f183383155b0a763f46039a93bf048604a5a1f95529a3b4b9b6511b5767c846d`. The added Run is a real 0.70-second Mixamo take; Walk is no longer sped to 2.8× as a substitute for running. The native Idle, Walk, Attack, Hit, Death and Mine animation data, rig nodes, inverse binds, body geometry, textures and sickle/socket remain unchanged. The original binary buffer is an exact prefix of the candidate's buffer.

The authorized donor is `Characters/Arthas/Animations/Mixamo_ActionAdventure/running.fbx`. `tools/enemy-locomotion-source.py` imports it in an independent factory-started Blender and exports armature/motion only to `assets/models/orc-peon-source/mixamo-running.glb`. The donor is checked before/after and never saved. This process never opens or saves the Orc Animation Master blend. `assets/models/orc-peon-source/provenance.json` records the donor hash and Blender version. Aldric's sword-run files were inspected but are ASCII FBX unsupported by Blender's importer; they were not modified or used as an undocumented conversion.

`tools/enemy-locomotion-build.mjs` transfers 22 mapped bones using world rest-orientation deltas and the animated target parent's inverse orientation. Target local translations, twist-bone chains, rig, skin and sickle parenting remain intact. Hip vertical motion is scaled by leg length; horizontal donor travel becomes stride metadata, with gameplay remaining responsible for actor translation. The final 80 ms closes the small donor rotation seam. A constant floor offset preserves the flight phase instead of pulling each airborne frame down to the ground.

The controller scales nominal stride with actual actor size and selects Run above 1.5× nominal Walk speed, returning to Walk below 1.25× to prevent boundary chatter. Walk is capped at 1.5×, Run at 2×; the exact mismatch is reported when a rate limit is reached. `update(dt,{speed,dead})`, `attack`, `hit`, `reset`, `dispose`, material isolation and pool ownership remain compatible. The pool may also pass `velocity` and `teleport`; the Orc controller currently consumes scalar speed, so directional contact locking is still pending.
